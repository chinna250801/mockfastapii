# V1 Backend — Task List

**Goal:** Build the full V1 backend from scratch for the AI mock test platform.

**Structure for every feature:**
- `app/models/` — database tables (SQLAlchemy)
- `app/schemas/` — request and response shapes (Pydantic)
- `app/repositories/` — database queries
- `app/services/` — business logic
- `app/api/routers/` — API endpoints (thin, just call services)
- `app/core/` — config, security, JWT
- `app/db/` — database session and base

**Roles:** admin and student. Auth uses JWT. DB is PostgreSQL.

---

## Task 1: Project setup

- Create folder structure (`app/`, `app/models/`, `app/schemas/`, `app/repositories/`, `app/services/`, `app/api/routers/`, `app/core/`, `app/db/`, `tests/`)
- Create `requirements.txt` (fastapi, uvicorn, sqlalchemy, psycopg, pydantic, pydantic-settings, pyjwt, bcrypt, httpx, pytest)
- Create `app/core/config.py` — settings loaded from `.env` (DB url, secret key, token expiry, AI keys)
- Create `app/db/base.py` — SQLAlchemy Base
- Create `app/db/session.py` — engine, SessionLocal, `get_db` dependency
- Create `app/main.py` — FastAPI app + health endpoint
- Create `.env.example`
- Smoke test: app starts, `GET /health` returns ok

## Task 2: User model

- Create `app/models/user.py` — id (UUID), name, email (unique), hashed_password, role (admin/student), is_active, created_at
- Add table creation on startup
- Test: table created correctly

## Task 3: Core security helpers

- Create `app/core/security.py` — `hash_password`, `verify_password`, `create_access_token`, `decode_access_token` (JWT, HS256)
- Test: hash/verify round trip, token create/decode round trip, bad token returns None

## Task 4: Auth — signup, login, me

- Create `app/schemas/auth.py` — SignupIn, LoginIn, TokenOut, MeOut
- Create `app/repositories/user_repo.py` — get by email, get by id, create
- Create `app/services/auth_service.py` — signup (email unique check, hash password), login (verify password, return token), get current user
- Create `app/api/deps.py` — `get_current_user`, `require_admin`, `require_student`
- Create `app/api/routers/auth.py` — `POST /auth/signup`, `POST /auth/login`, `GET /me`
- Tests: signup ok, duplicate email 400, wrong password 401, /me without token 401, admin route blocked for student 403

## Task 5: Topics (admin)

- Create `app/models/content.py` — Topic table (id, name unique, created_by, created_at)
- Create `app/schemas/topic.py` — TopicIn, TopicOut
- Create `app/repositories/topic_repo.py` — create, list, get by id, get by name, update, delete
- Create `app/services/topic_service.py` — duplicate name check, only creator can edit/delete
- Create `app/api/routers/topics.py` — POST/GET/PATCH/DELETE `/topics` (write = admin)
- Tests: create, duplicate name 400, student forbidden 403, update, delete

## Task 6: Questions with options (admin)

- Add to `app/models/content.py` — Question (topic_id, difficulty, question_text, explanation, created_by) and Option (question_id, option_text, is_correct, display_order)
- Create `app/schemas/question.py` — QuestionIn (with options list), QuestionOut; validate exactly one correct option
- Create `app/repositories/question_repo.py` — create with options, list with filters (topic, difficulty, created_by), get, update, delete
- Create `app/services/question_service.py` — topic must exist, difficulty in Easy/Medium/Difficult
- Create `app/api/routers/questions.py` — POST/GET/PATCH/DELETE `/questions` (admin only)
- Tests: create ok, no correct option 400, two correct options 400, filters work, student forbidden

## Task 7: Start a test (student)

- Create `app/models/attempt.py` — Attempt (student_id, topic_id, difficulty, total_questions, time_limit_minutes, score, status, started_at, submitted_at) and AttemptQuestion (attempt_id, question_id, selected_option_id, question_order, is_correct, time_spent_seconds)
- Create `app/schemas/attempt.py` — StartTestIn (topic_id, difficulty, num_questions 1–20, time_limit_minutes), StartTestOut
- Create `app/repositories/attempt_repo.py` — create attempt, bulk insert attempt_questions
- Create `app/services/test_service.py` — `start_test`: random questions matching topic+difficulty+count; return actual count if fewer exist; error if none
- Create `app/api/routers/tests.py` — `POST /tests/start` (student only)
- Never expose correct answers in the response
- Tests: start ok, fewer available than requested, zero available 400, limits 1–20 and time > 0

## Task 8: Answer questions during a test

- Add to `app/schemas/attempt.py` — AnswerIn (question_id, selected_option_id nullable, time_spent_seconds)
- Add `PUT /tests/{attempt_id}/answer` — save answer + time, only while in_progress and owner
- Add `GET /tests/{attempt_id}/state` — question palette: answered / skipped / marked + time spent
- Auto-reject answers after time limit or after submit (409)
- Tests: answer saved, skip allowed, answer after submit 409, other student's attempt 404

## Task 9: Submit test and scoring

- Add `POST /tests/{attempt_id}/submit`
- Unanswered questions count as wrong
- A previously skipped question answered correctly before submit counts as correct
- Set score, status = submitted, submitted_at; double submit returns 409
- Tests: scoring counts unanswered as wrong, skipped-then-correct counts, double submit 409

## Task 10: Result page

- Add `GET /tests/{attempt_id}/result`
- Score as correct/total
- Solutions only for wrong answers (correct option + explanation)
- Time spent per question
- Student sees only own result
- Tests

## Task 11: AI feedback

- Create `app/repositories/feedback_repo.py` and extend `app/models/attempt.py` — AIFeedback table (attempt_id, strongest_area, weakest_area, improvement_suggestion, full_feedback_text)
- Create `app/services/feedback_service.py` — build payload (correct topics, wrong topics, time per question, accuracy), call OpenAI or Gemini per config, save result
- Create `app/schemas/feedback.py` — FeedbackOut
- Hook into submit; if AI call fails, the test result still works
- Add `GET /tests/{attempt_id}/feedback`
- Tests (mock the AI call)

## Task 12: Student dashboard

- Create `app/schemas/dashboard.py` and `app/services/dashboard_service.py`
- Add `GET /dashboard` — past attempts with date/topic/difficulty/score, accuracy per topic, simple daily/weekly score trend
- Student sees only own data
- Tests

## Task 13: Admin lists

- Add `GET /admin/topics` and `GET /admin/questions` — only content created by that admin, with topic name + difficulty
- Tests

## Task 14: Final wiring and smoke test

- Register all routers in `app/main.py`
- Add AI SDK to `requirements.txt` and env keys to `.env.example`
- Run full `pytest`
- Manual smoke: signup → login → create topic/question → start test → answer → submit → result + feedback → dashboard
